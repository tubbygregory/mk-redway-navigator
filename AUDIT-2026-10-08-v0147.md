# Cultural Route loading follow-up — 8 October 2026

The user's installed-iPhone recording shows Explore failing to load a full Cultural Route, then opening a blank external browser from the GPX fallback link. The current release is v0.14.6 at main `3fd90f6a3c8d825526d3f602eb651f28fec23305`; PR #14 and its production workflow succeeded. There are no open PRs at the start of this follow-up.

## Confirmed findings, in priority order

1. **High — Cultural Route loading depends on a browser-blocked source request.** All ten URLs remain linked by the official Get Around MK Cultural Routes page. Verified HTTPS requests returned valid GPX with HTTP 200 but no `Access-Control-Allow-Origin`. The app's cross-origin `fetch` cannot consume these responses. Some environment requests also received HTTP 403; source access is not consistently available. Publish unchanged, source-verified GPX as same-origin runtime assets and precache them. Validate every source hash and actual UI load, including offline root/subpath deployments.
2. **Medium — the fallback opens an external GPX page instead of reliably downloading a file.** The existing target-blank link hands an installed PWA to a browser. The recording demonstrates an unusable blank page; the prior browser assertion stopped before clicking that link. Keep failure reporting and Retry inside Explore, preserve an existing route, and retain explicit import guidance and the official guide link. Test real successful clicks, HTTP/malformed failures and retry without a popup or page handoff.
3. **Medium — “Short route” misrepresents the official short GPX.** Each full file is a closed loop; each short file is an open shortcut segment. The short files measure approximately 0.345–4.027 km, whereas the guide describes complete 4/5-mile shorter rides. Label them “Shortcut track”, explain the distinction and qualify the guide distances. Preserve every original coordinate; do not infer connecting paths or fabricate shorter loops.
4. **Medium — the destination panel covers bottom navigation.** Real pointer testing after returning from the planner showed the Directions button/panel intercepting Explore clicks, both expanded and collapsed. Keep this panel above the navigation bar using the same safe-area spacing as Explore, bound its scrollable height, and verify all three navigation buttons remain reachable without clearing the destination.

## Scope and source handling

The `cultural-routes/manifest.json` records original URLs, verification date and SHA256 hashes. Only its manifest and ten validated, unchanged GPX files enter Pages; the source page, response headers and diagnostics remain outside the checkout/artifact. Council/Get Around MK attribution, upstream data rights and the independent-project disclaimer remain explicit. No council endorsement or permission claim is introduced.

The supplied MK artwork, app-red selected route, routing weights, navigation state guards and installed-iPhone dark surfaces are preserved. No backend, public CORS proxy, new dependency or inferred route variant is introduced. Future CI could avoid rebuilding geographic data for runtime-only changes while retaining freshness and release checks; that optimisation is deferred rather than bypassing current gates.
