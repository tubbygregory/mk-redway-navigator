# Reliability audit — v0.14.3

Baseline: main `3a039f0279d62ba34e28d536fbb390d2458ed487` (v0.14.2), with successful build/deploy/live-review/release and no open PRs. This audit preserves the fitted MKRW artwork and the product decisions documented in REVIEW-AUDIT.md.

## Confirmed defects and repairs

- **Offline handoff:** unseen query-string route URLs missed the exact app-shell cache key. Canonical document fallback now applies only to scoped root/index navigation, including subpath installs.
- **Offline reliability:** HTTP failures bypassed cached routing data, routine graph caching was deleted with the old shell, unsuccessful assets could poison caches, and cache write failures could disrupt responses. Graphs now use persistent offline storage, migrate from old shells, survive HTTP errors, and successful requests tolerate cache quotas.
- **PMTiles:** unsupported Range headers consumed the body before returning it; map interception also applied to unrelated origins. Range fallback stays readable and interception is restricted to the installed scope.
- **Delayed GPS:** a pending Start could resume after Back/route replacement; repeated taps could launch multiple requests. A cancellable start generation and in-flight guard prevent this. Stale rerouting completions cannot resume stopped navigation.
- **Inaccurate GPS:** poor fixes could count toward off-route detection and trigger rerouting. They now suspend progression, announcements and off-route counting until accuracy recovers.
- **Map renderer race:** old load callbacks/timeouts referenced the mutable global layer. They now act only on the instance that created them, with a second guard after availability probing.
- **Stale live-routing data:** fallback fetches now check the route revision before solving.
- **Offline download reporting:** swallowed graph download errors could still report success; failure text was immediately overwritten. A usable graph is required and failure feedback persists.
- **Graph validation:** the browser silently accepted malformed nodes/ways that the Python producer rejected. It now rejects invalid coordinates, duplicate IDs, missing references, non-string tags and unsupported classification values before installation.
- **Search pacing:** concurrent submitted/reverse searches could wake from the same delay and issue requests together. A shared asynchronous gate assigns separate actual request slots. Type-ahead remains local.
- **Release retries:** an existing beta tag may only be reused for the identical commit, rather than silently moved to a later deployment.

## Scope and verification

Producer/consumer v6 metadata, access/one-way rules, finite lit/Super Route preferences, snapping/approach gaps, maneuver generation, source attribution, GPX parsing/rendering/export, shared-URL parsing, theme handling and runtime artifact construction were reviewed. No routing weights, access rules, cultural-route claims or schema version were changed. Missing lighting stays unknown; crossing estimates and source-GPX availability limitations remain explicit.

Required gates: Python validation/unit tests; JS syntax; all Node tests including 24 representative MK journey/mode combinations; browser, mobile/PWA and focused audit suites at 390×844, 844×390 and 1280×900; root/subpath offline shared navigation; delayed GPS cancellation; actual uploaded Pages archive inspection; deployment; repeated live-site PWA/audit suites. These gates run before publication. CI logs on the associated PR and main run are the authoritative final results.

New controlled regressions exercise real service-worker/application functions with fetch/cache/GPS/layer mocks. Real-browser tests separately verify offline navigation and cancelling Start through the UI. Existing tests remain mandatory.

Physical cycling and an actual installed iPhone remain necessary for real GPS jitter, speech/background suspension, battery use, launcher caching and current path conditions. Emulation cannot establish those outcomes.
