This follow-up implements the illustrated design review and friendliness assessment of v0.14.9. The reference release was `722cf7121be471dc1b033b66b78a5a561c926b5f`; GitHub was rechecked before implementation. The approved stylised MK artwork, app red, Cultural Route colours and existing routing/data semantics remain constraints.

## Friendliness

- Explain how to add favourites and Home/Work in empty states.
- Offer Undo for removed favourites, restoring into the latest durable collection without overwriting intervening edits or ignoring storage/capacity failures.
- Keep MK coverage and address precision honest while offering postcode editing or a map pin after an unsuccessful search.
- Distinguish denied location permission, timeout and unavailable GPS; offer manual search without an unexpected prompt.
- Say “Ready for offline journeys” only after the map and routing cache are validated, retaining size and device-storage caveats.
- Keep a named arrival summary until Done or a new journey; retain existing GPS-gated arrival detection and speech.

## Validation and limits

Release validation covers Python data tests, JavaScript syntax and regressions, representative generated-network journeys, browser/PWA/audit checks, a focused rendered design gate, and inspection of the actual Pages archive. The design gate exercises native link/button hit testing, narrow layouts, favourite naming/Undo, search recovery, route actions and arrival. Deployment and production verification remain required before this release is complete.

The changes do not alter routing weights, network v6, legal access, source-track geometry, geographic claims or official route properties. No new dependencies, accounts, backend, remote naming service or location requests per keystroke are introduced. Required OpenStreetMap/Protomaps credit, factual Get Around MK source attribution and the independent-project notice remain.

Physical Safari/iPhone safe areas, keyboard/dynamic text, sunlight readability, touch accuracy and riding GPS/audio/background behaviour still require device review. Chromium emulation cannot establish those behaviours.

## CI opportunities retained for later

The UI work reuses validated geographic data locally. CI retains its current data-generation and release gates, including current-source attempts with validated cache fallback; these are not bypassed for a styling release. Future optimisation can cache checksum-verified runtime dependencies and reuse browser installation artifacts, provided validation and the actual deployment-archive inspection remain mandatory.
